# Configuration and privacy

Preferences use `os.UserConfigDir()/siftpane/config.json`: normally `~/Library/Application Support/siftpane/config.json` on macOS, `$XDG_CONFIG_HOME/siftpane/config.json` or `~/.config/siftpane/config.json` on Linux, and `%AppData%\siftpane\config.json` on Windows. Override with `--config PATH`. See [example configuration](../examples/config.json); do not copy placeholder IDs unchanged.

Inclusion and local-read maps are keyed by **workspace ID then conversation ID** so saved preferences cannot bleed between workspaces. The application still uses one workspace at a time. Writes use a private temporary file and rename; tokens and bodies never enter this file. There are no default application logs. A corrupt configuration is reported rather than overwritten. Use one Siftpane process per config file; concurrent writers are not coordinated.

Included conversation display summaries are cached separately in `CONFIG_PATH.<account-hash>.metadata.json`, alongside the selected config file. The hash separates workspace and authenticated user identities; it contains no credential. Cache files use private permissions and atomic replacement. Each holds at most 64 summaries / 64 KiB, expires seven days after saving, and is safe to delete while Siftpane is closed. Missing, corrupt, expired, future-dated or unsupported cache data falls back to live restoration without changing preferences. A failed cache write is shown in the status row and does not prevent messaging.

Only IDs, names, available handles, conversation kinds and member counts are cached, for included conversations only. Topics, purposes, message bodies, drafts and tokens are excluded. Cached names are display hints, not proof of current access or a complete workspace directory. Every startup still refreshes metadata through the existing paced calls. Demo and snapshot runs remain memory-only.
