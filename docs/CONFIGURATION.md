# Configuration and privacy

Preferences use `os.UserConfigDir()/siftpane/config.json`: normally `~/Library/Application Support/siftpane/config.json` on macOS, `$XDG_CONFIG_HOME/siftpane/config.json` or `~/.config/siftpane/config.json` on Linux, and `%AppData%\siftpane\config.json` on Windows. Override with `--config PATH`. See [example configuration](../examples/config.json); do not copy placeholder IDs unchanged.

Inclusion and local-read maps in `account_preferences` are keyed by **workspace ID/authenticated user ID**, then conversation ID. `accounts` contains only verified workspace/user IDs and display names; `default_account` records the last login. Secrets remain in the OS credential store, keyed by the same workspace/user pair. Only the active account reads or discovers. Writes use a private temporary file and rename; tokens and bodies never enter this file. There are no default application logs. A corrupt configuration is reported rather than overwritten. Use one Siftpane process per config file; concurrent writers are not coordinated.

Included conversation display summaries are cached separately in `CONFIG_PATH.<account-hash>.metadata.json`, alongside the selected config file. The hash separates workspace and authenticated user identities; it contains no credential. Cache files use private permissions and atomic replacement. Each holds at most 64 summaries / 64 KiB, expires seven days after saving, and is safe to delete while Siftpane is closed. Missing, corrupt, expired, future-dated or unsupported cache data falls back to live restoration without changing preferences. A failed cache write is shown in the status row and does not prevent messaging.

Only IDs, names, available handles, conversation kinds and member counts are cached, for included conversations only. Topics, purposes, message bodies, drafts and tokens are excluded. Cached names are display hints, not proof of current access or a complete workspace directory. Every startup still refreshes metadata through the existing paced calls. Demo and snapshot runs remain memory-only.

Resolved author/mention names use a second disposable file, `CONFIG_PATH.<account-hash>.profiles.json`. It contains only user IDs, display names, handles and successful lookup times, including names encountered through loaded directory metadata. It holds at most 512 entries / 256 KiB; individual entries expire seven days after lookup, and unrelated saves do not renew them. Missing, corrupt, oversized or unsupported data falls back to ID labels and paced name lookups. Message bodies, complete Slack profile responses (including email/avatar/status fields), drafts and credentials are excluded. It is safe to delete this file while Siftpane is closed. Demo/snapshot runs still use no disk cache.

## Durable attention state

`CONFIG_PATH.<account-hash>.attention.json` stores account-specific Kept IDs, pending/handled trigger identities and typed reasons, timestamps/thread targets, source enablement, the message-cache opt-in, up to 32 explicitly followed thread roots with completed watermarks, last successful check/checkpoint, a monotonic replay floor and optional known-gap bounds and an acknowledgement watermark. The existing workspace/user hash separates authenticated accounts. It contains no token, body, draft, channel topic or private permalink. Writes use private permissions and atomic replacement. The format is versioned, bounded to 512 KiB, 128 active attention conversations and 1,000 combined active/handled identities. Kept has its separate UI limit of 32.

This file is durable preference/replay state, not a disposable cache: deleting it can restore previously dismissed mentions. Corrupt, oversized and unknown-version files are reported and never silently replaced. Preserve the file and recover it before making attention changes. First use migrates existing included IDs to Kept for that account; later account-specific state is authoritative, with inclusion mirrored in the account-specific preferences. Discovery is off by default and remains isolated by workspace and authenticated user.

Handled identities expire only behind the persisted replay floor; enabled scans cannot expand backward across that floor after pruning or re-enabling. Pending attention stays until explicitly dismissed, even when old. A write failure leaves the row and checkpoint intact. This state is independent of optional/disposable message and display caches. Demo and snapshots remain memory-only. Explicitly opened temporary conversations can contribute disposable display summaries; unopened search discoveries do not.

Known-gap bounds are a backward-compatible optional field in attention format version 1. They summarize the earliest and latest uncovered intervals, including any checked periods between separate gaps. Successful scans do not clear them. Only a confirmed, durably saved `Ctrl+G` acknowledgement clears the warning; failed saves retain it. Acknowledgement records a separate watermark so replaying the same failed interval cannot resurrect the warning. Newly uncovered time beyond that watermark still warns. This does not claim that the missed history was checked.

## Optional recent message cache

Disk content caching starts **off**. In navigation, press `Ctrl+B` twice after the disclosure to enable it for this authenticated workspace/user. It stores Slack content locally, unencrypted, in `CONFIG_PATH.<account-hash>.messages.json`, separate from preferences, credentials and durable attention. `Ctrl+B` once disables an enabled cache and removes this account's file. `Ctrl+X` clears the file without disabling future caching. Neither action discards drafts or sends anything. An intervening key cancels enablement; held-key repeats cannot confirm it.

The disposable version-1 file uses atomic replacement and owner-only permissions (0600, with newly created directories 0700). It holds at most **16 Kept conversation windows**, **100 messages per conversation**, and **4 MiB total**, expiring each window **24 hours after its successful live fetch**. Rewriting another window does not renew it. Startup and later writes trim expired or no-longer-Kept windows on disk even if live fetching fails; cleanup errors remain visible. Most recently fetched windows win; messages larger than 64 KiB are skipped, and completely oversized windows are omitted. Content may include fetched text, blocks, file links and attachment fallback text. Client send IDs and decorated author names are omitted. This is a fetched display aid, not an archive or complete offline mirror; message timestamps may predate the cache's fetch time.

Only subsequent successful recent conversation pages for Kept conversations qualify after enabling. Thread replies, older/anchored pages, unopened attention discoveries, composed drafts and outbox attempts are excluded. No history downloads are added to fill the cache. Restoring it creates no sends, retries, local unread activity or read-position changes. Live refresh uses the existing stable timestamp reconciliation and pacing. Until it succeeds, the footer labels the window cached, shows its fetch time, and distinguishes refresh failure from an empty live history. Cached content never proves current access or freshness. Missing display metadata uses an ID placeholder until its live response arrives.

Missing, corrupt, unsupported, oversized, expired or future-dated files fall back to live fetching. Write failures do not block messaging. Removing Kept status removes its persisted window and cancels associated local follows; explicit access denial purges that conversation's disk window and visible cached history, cancels its reads and invalidates their generations before retry. Authentication failure stops reads and clears the account file. A cache epoch prevents reads already running at clear/disable/removal/revocation from repopulating disk. Future successful normal fetches can populate it again if enabled. Removal failures remain visible and can be retried with `Ctrl+X`; a disabled cache also attempts cleanup on startup. Other account files are untouched. Use one process per config path, as with preferences.

Local following is also account-specific: `f` in an opened thread persists its root and the current time, then checks future replies from other authors. It neither imports nor changes Slack's follow/notification settings. Follow state, handled attention and gap acknowledgement survive clearing or disabling the disposable message cache. Demo and snapshots keep all these stores memory-only.


## Multiple accounts and migration (0.7)

Repeat `--login` to save separate credentials; `--account WORKSPACE_ID/USER_ID` selects the initial account and `Ctrl+W` switches in-session. A `SIFTPANE_SLACK_TOKEN` override supplies one session-only account and suppresses saved accounts for that run; it is never persisted. `--logout --account WORKSPACE_ID/USER_ID` deletes only that credential and registry entry, retaining preferences and durable dismissals. Without `--account`, logout targets the last login (or the legacy credential when no account default exists). To clear opted-in content before logout, select that account and use `Ctrl+X` or disable caching first.

On first normal launch with no registry, the saved `siftpane` / `user-token` credential is authenticated, copied to its workspace/user key, and recorded before the legacy entry is deleted. A failed replacement/save keeps the original credential. If deletion fails, the old entry remains with a warning. Legacy workspace inclusion/read preferences move once into the first verified account's preferences for that workspace. Existing account-hashed attention, metadata, profile and message files retain their filenames and scope. Launch once with the existing saved credential before adding another user of the same workspace so the intended user claims legacy preferences. Back up the config first; older versions do not understand the new account preferences and cannot safely share the upgraded config.

Each visited account retains bounded caches, drafts/outbox and view state in memory for the process lifetime. There is no disk draft recovery or inactive polling. Startup validates saved credentials with `auth.test`; unavailable non-selected accounts are skipped with a reconnect instruction, while an explicitly selected unavailable account requires another `--account` or `--login`. Failed default accounts do not prevent a healthy account from opening. Credentials expiring during a session stop only that account; reconnect with `--login` and restart after copying any drafts.
